# Архитектура проекта «Отдых.23»

---

# Главный принцип

Проект построен на универсальной архитектуре.

Нельзя создавать отдельный HTML, CSS или JavaScript под отдельную комнату.

Все категории используют единый шаблон.

---

# Структура проекта

```
css/
js/
data/
images/
knowledge/
index.html
```

---

# data/

Каждая категория комнаты хранится отдельно.

```
comfort.json
deluxe-2.json
deluxe-3.json
family.json
```

Каждый JSON является самостоятельным источником данных.

---

# images/

Фотографии хранятся по категориям.

Внутри каждой категории фотографии разделены по сценариям размещения.

Главная фотография всегда имеет префикс

00_

Остальные изображения автоматически попадают в мини-галерею.

---

# knowledge/

Здесь находится вся база знаний проекта.

При изменении текстов сначала обновляются документы knowledge.

После этого синхронизируются JSON.

JSON не является основным местом хранения текстов.

---

# ROOM_CATALOG

ROOM_CATALOG используется как единый каталог комнат.

Если JSON успешно загружен — ROOM_CATALOG обновляется автоматически.

Если JSON недоступен — используется fallback.

---

# Карточки комнат

Все карточки строятся автоматически.

HTML не содержит готовых карточек.

Карточки создаются JavaScript.

---

# Просмотр комнат

Для всех категорий используется единый Room Viewer.

Нельзя создавать отдельное окно просмотра под конкретную категорию.

---

# Галерея

Каждый сценарий имеет собственную галерею.

Миниатюры строятся автоматически.

Lightbox общий для всех категорий.

---

# Кнопка «Проверить даты»

Используется единый механизм.

Кнопка всегда ведёт к

#booking

---

# Добавление новой категории

При добавлении новой категории необходимо:

1. Создать JSON.

2. Создать папку с фотографиями.

3. Разложить фотографии по сценариям.

4. Главное фото назвать с префиксом

00_

5. Подключить JSON.

Никаких изменений HTML делать не нужно.

---

# Добавление новых фотографий

Для добавления фотографий достаточно положить изображения в нужную папку.

Код галереи изменять нельзя.

---

# Что запрещено

Запрещается:

• создавать отдельные карточки;

• создавать отдельные модальные окна;

• создавать отдельный JavaScript под комнату;

• дублировать код;

• менять структуру JSON;

• менять структуру knowledge без согласования.

---

# Основной принцип разработки

Максимум универсальности.

Минимум дублирования.

Все новые возможности должны работать сразу для всех категорий.
